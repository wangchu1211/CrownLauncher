# Crown 构建工作台方案

文档类型：Design / Roadmap

状态：第一版已接入 CBT，日常构建闭环及真实窗口定向验收已通过

日期：2026-10-12

## 目标与产品位置

构建工作台让用户在不深究构建代码的情况下，仍能检查配置、理解 AI 的操作、启动构建并
验收结果。入口为 CrownLauncher 的 **Build** 页面，独立于 Editor：即使 Editor 尚未构建或无法
启动，工作台也应可用。现有 Projects、Samples 与项目管理流程继续保留。

用户从 UI 操作，AI 和自动化继续使用 CLI。两者复用同一个 CBT 执行逻辑和任务记录，
用户也能在 UI 中看到 AI 发起的构建，不要求 AI 模拟点击按钮。UI 不再维护另一套
模块规则、目标列表、依赖图或功能默认值；这些信息应从 CBT 查询。

## 用户需要看懂的五件事

| 问题 | 界面应呈现的内容 |
| --- | --- |
| 正在构建什么？ | 工作区、分支、提交、未提交修改；目标（如 Editor、Player、Profiler）、Debug / Development / Shipping，以及实际启用的 Features 和作用。 |
| 为什么需要构建？ | 变化的模块、可复用的编译结果、缓存失效原因、需要准备的依赖。无变化时也应解释 no-op，而非只显示瞬间成功。 |
| 现在进行到哪里？ | 准备依赖、生成代码、编译、链接、部署各阶段，真实任务数量、耗时、错误摘要、排队与取消状态。详细日志是可展开的第二层。 |
| 得到了什么？ | 产物路径、对应源码版本、配置、Features、产物清单；按实际产物提供启动 Editor、打开 LookDev 或查看打包结果等操作。 |
| 验证到什么程度？ | 分开展示构建结果、实际运行的测试及结果、跳过和未验证项，以及人工体验待确认的内容。编译通过不等于功能符合预期。 |

显示无法准确量化的阶段时，使用阶段名称与实际计数，不伪造整体百分比或剩余时间。
错误摘要保留原始诊断入口，不能用一句 AI 总结替代编译器或测试结果。

## 执行与数据边界

工作台沿用 [Electron 架构](architecture/electron-launcher.md)：Renderer 通过类型化
preload API 发起受约束的请求，Main 校验工作区、参数与允许的操作，再调用 CBT。
Renderer 不获得任意 shell、任意进程控制或任意目录删除能力。

第一版复用 CBT typed graph、原生构建锁、BuildReport 和产物发布验证，增加 schema v1
的 `workbench` 查询与任务合同。以下边界同时约束后续扩展：

- **能力查询**：版本化 schema，列出当前工作区真正支持的目标、配置、Features 和约束。
- **结构化事件**：稳定的任务 ID、阶段、计数、诊断、退出状态和取消结果。人类可读日志
  用于排查，不作为唯一状态解析来源。
- **持久任务记录**：UI 与 CLI 都写入同一合同，记录发起方式、工作区、源码身份、请求
  配置与实际配置、时间、日志、结果、产物及验证范围。重新打开 Launcher 后仍可查询。
- **产物关联**：仅将本次实际产物与任务关联；构建失败后不得把旧产物冒充本次成功结果。
  未提交修改必须明确标记，不能只用分支或 commit 声称可复现。

CBT 仍负责执行、缓存、锁和依赖准备。工作台展示等待锁、排队、运行、取消、失败、
中断和成功等真实状态，不引入第二个构建调度器。取消只针对任务所属进程，不能结束
其他 Editor 或其他工作区构建。Launcher 关闭时，要明确提示运行任务如何处理；重启后
能区分仍在运行与异常中断的任务，不丢失记录或自动重试。

当 CBT 自身无法启动或工具链缺失时，先显示 bootstrap / 环境诊断，不能让工作台跟随
Editor 一起失效。缓存清理如果后续加入，必须预览准确路径、预计影响和受保护目录，
再由用户确认，不因构建失败自动清空缓存。

## 测试与验收由用户把控

日常构建不自动执行完整 Standard。测试是独立选择：展示所选范围、预计工作内容和
实际结果；需要完整 Standard 时由用户明确启动。此方案不恢复之前暂停或关闭的 CBT
goal，也不把未执行的验证显示为通过。

建议每条任务分别记录：构建状态、自动化验证范围、未验证项、人工验收状态。人工体验
确认由用户给出，AI 不应替用户确认。历史结果要显示其对应源码与配置，避免用户把旧
版本的一次通过误认为当前版本已验收。

## 分期与验收标准

### 已完成的 Launcher 外观

参考用户提供的 Codex 桌面界面，使用暖黑底色、细分隔线和克制圆角。左侧固定为 52px
纯图标栏，只保留 Projects、Samples、Build 和设置；悬停或键盘聚焦时显示说明，不再
展示重复文字导航、展开按钮或侧栏项目列表。项目在 Projects 页面管理，设置提示保留
Editor 就绪状态。Build 沿用同一套设计令牌，不改变已有项目管理流程。

界面支持 `Ctrl+=` / `Ctrl++` 放大、`Ctrl+-` 缩小及 `Ctrl+0` 复原，也支持小键盘加减号。

### 第一版的已实现范围

选择包含 `CrownBuild.ps1` 的源码目录，连接后从 CBT 获取 Target、配置、平台及 Features。
只连接可信源码：连接会通过公开 bootstrap 编译并执行该工作区的 C# 构建规则，不构建
引擎。配置摘要显示模块和源码条目；真正的缓存验证交给开始构建后的原生 executor。

Build 创建后台任务；Build & Run 经页面确认后构建并运行对应产物，任务直到产品退出才
结束，取消会停止该任务启动的产品。关闭 Launcher 不结束后台任务；重新连接同一工作区
可查询任务。普通 CLI `build` / `run` 同样记录，沿用命令行退出码和调用方生命周期。

任务详情显示真实阶段、耗时、源码身份、Features、图指纹、产物路径与最新 64 KiB 日志；
完整日志可在文件管理器打开。源码身份是在请求时采集的，工作树没有冻结，排队期间的
修改也可能影响最终构建。产物路径是共享发布位置，后续构建可能替换它，因此历史记录
只提供查看文件，不提供跳过 CBT 验证的旧产物启动按钮。

构建、自动化测试、人工验收分别展示。构建不是测试：第一版显示 Tests Not run、Human
Acceptance Pending，不能据此声称 Standard 或产品功能验收通过。

### 后续：扩展到其他构建入口

在第一版可靠后，逐步接入打包、显式测试、依赖准备与必要的缓存管理。具体入口由 CBT
能力查询驱动，不先在 UI 中硬编码一张“大而全”的菜单。

云构建、分布式调度、远程执行及复杂依赖图编辑暂不做。性能优化优先解决能显著缩短
等待的大头，不为微小收益增加一套复杂机制。

## 数据与刷新合同

CBT 将记录保存在各工作区 `Build/CBT/Workbench/Jobs/<id>/`：`job.json` 保存请求与
生命周期，`progress.json` 保存最新阶段，`result.json` 仅由本次构建验证生成，`output.log`
保存完整输出。无关旧 BuildReport 不会填入新任务；异常退出根据 PID 和创建时间识别，
不自动重试。取消由 CBT worker 的 kernel job containment 停止自己的进程树。

Launcher 每 1.5 秒查询当前工作区，展示最近 100 条记录，不全盘扫描所有仓库。已连接
工作区列表位于 Launcher 配置目录的 `workbench.json`，最多保存 12 个路径。
查询使用连接时的不可变 CBT runtime；修改构建规则后点 Reconnect 更新配置列表与摘要。
每次实际构建仍走公开 `CrownBuild.ps1` bootstrap 校验当前工具和规则，避免使用旧规则。

当前不回填此功能加入前的构建，也不记录 `test`、`export`、Setup 或直接调用内部 API
的操作。不跨工作区聚合历史，不保存每个动作的事件流或整体完成百分比；细粒度缓存
失效解释、测试与打包入口、不可变历史产物启动、任务清理和人工验收签字均留待后续。
记录存放于生成目录，手动清理对应目录会丢失该工作区历史。

## 当前验证范围

已通过 Launcher 单元测试、类型检查和打包，以及 CBT 能力查询、真实 Probe 构建/运行、
等待锁、取消、中断、真实编译失败不误用旧产物和中文路径日志等定向检查。真实 Launcher
窗口已验证连接、配置与 Feature 切换、UI 发起 Probe 构建、CLI 历史、等待锁、关闭重开
后恢复运行任务、界面取消及窄窗口布局。未执行完整 Standard；未重建或运行 Editor 等大型
产品来扩大此次 UI 验收范围。

相关文档：[Project Manager MVP](project-manager-mvp.md)。Build 是原项目管理 MVP 之外
新增的独立源码构建能力，不改变已安装 Editor 的 Projects / Samples 启动合同。
